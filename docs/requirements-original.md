# Coding Agent 自动化开发系统需求

> 记录日期：2026-10-17。
> 来源：用户提供的原始需求。以下正文保留原文，分析与建议另见 [需求分析](requirements-analysis.md)。

## 1. 项目目标

搭建一套本地自托管的编程 Agent 自动化系统，使用 n8n 编排流程，调用 Claude Code CLI 和 OpenAI Codex CLI，自动完成从任务规划、代码实现、Review 到 Git 提交的开发闭环。

## 2. 核心工作流程

1. **分析项目**：分析代码仓库，生成并拆分开发任务，明确任务依赖和验收标准。
2. **执行任务**：选择可执行任务，使用独立的 Git Worktree 和新的 Agent 会话完成编码。
3. **代码 Review**：启动全新的 Agent 会话，独立检查代码和测试结果。
4. **修改与复审**：Review 不通过则启动新的 Fix 会话，修改后重新 Review。
5. **提交代码**：只有 Review 通过后才允许 Git Commit。
6. **持续循环**：分析当前进度，生成后续任务并继续执行，直到没有可执行任务或触发停止条件。

## 3. 核心要求

- 支持 Claude Code CLI 和 Codex CLI，可配置默认 Agent。
- Planning、Coding、Review、Fix 每个阶段均使用独立的新会话。
- 不同任务使用独立 Worktree，避免代码相互干扰。
- 使用 SQLite 持久化项目、任务、执行状态、Review 结果和日志。
- 支持任务依赖、失败重试、超时、取消、暂停和恢复。
- 支持人工审批、最大重试次数、Review 轮数和运行预算限制。
- 通过结构化结果判断 Review 是否通过，不能依赖模糊的自然语言判断。
- 无任务时等待，不得无限空转；达到停止条件后自动结束。

## 4. 技术架构

- **n8n**：流程编排、审批、等待和通知。
- **Python + FastAPI**：Agent Runner，负责任务调度、状态机、CLI 调用和 Git 操作。
- **SQLite**：本地持久化存储。
- **Git Worktree**：任务隔离。
- **Docker Compose**：统一部署和管理服务。

## 5. 安全与实施要求

- Agent 默认只能操作指定仓库和任务工作区。
- Review 尽可能采用只读权限。
- 默认禁止自动 Push、Merge 和部署。
- 任务状态以 Runner 为准，确保重启后可恢复。
- 先实现基础功能和自动化测试，再逐步接入真实 Agent 与 n8n 自动循环。

**最终目标：** 实现一个能够自主规划任务、循环编码、独立审查、按需修复、通过后提交，并持续推进开发工作的本地 Coding Agent 系统。
