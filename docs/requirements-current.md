## 1. 项目目标与任务范围

| ID | 已确认需求 |
|---|---|
| C01 | 构建本地自托管的 Agent 自动化任务系统，以开发任务为核心场景，并支持非编程任务。 |
| C02 | 支持注册多个目标仓库；第一版运行范围限定为一个项目。 |
| C03 | 根据项目目标分析任务、拆分任务，明确任务依赖和验收标准，并持续推进可执行任务。 |
| C04 | 能并行执行时优先并行；无法并行时允许串行编排任务。 |

“第一版运行一个项目”不意味着只能注册一个仓库，也不意味着项目内只能运行一个任务。一个项目是否关联多个仓库、是否支持跨仓库任务，尚未确定。

非编程任务不强制套入 Coding、Worktree、Git Commit 或 Merge 流程。具体首批任务类型、产物和执行工具，尚未确定。

| C46 | Worktree 与分支清理可分别追踪和重试；清理失败不把已完成的任务或集成改为失败，也不回滚已完成成果。 |

### 5.1 对原始 Merge 边界的更新

原始需求为“默认禁止自动 Push、Merge 和部署”。后续补充已明确支持最终合并，并采纳受控集成流程，因此 Merge 不再作为一概禁止的最终能力。

当前有效要求为：**系统支持成果合并，只有满足配置的验证、Review 和批准条件后，才能更新目标分支。** 自动合并范围、默认批准点和具体目标分支仍待确定。

默认禁止自动 Push 和部署的要求仍有效。本需求更新没有授权当前会话对实际仓库执行 Merge、删除分支、清理 Worktree 或向外部系统发送内容。

### 5.2 完成与清理的语义

- 任务完成：产物满足任务验收；需要提交的代码任务已有通过门禁的提交。
- 集成完成：相关代码成果进入指定目标分支，并通过该集成流程的组合验收。
- 清理完成：Worktree、临时资源和任务分支按适用清理政策完成处理。

三个结果可独立追踪。非 Git 任务的集成和 Git 清理标记为不适用；是否清理其临时产物由相应产物保留政策决定。

集成验证必须绑定具体候选内容、目标 HEAD 和任务提交。若集成需要生成新的 Merge Commit 或其他新提交，须先完成适用的候选 Review，再创建提交；不能为形成候选而提前创建未经审查的正式提交。任务分支已有 Review 不能替代集成后所需的验证或 Review。

### 5.3 尚未确定的集成与清理政策

- 最终目标分支名称及专用集成分支与最终分支之间的关系。
- 合并方法、自动放行条件、必须 Review 的范围及人工审批默认位置。
- 冲突默认交人工还是有界自动修复，以及具体次数和预算。
- 下游任务使用已审查提交还是已集成成果作为基线的条件。
- 清理由人工触发还是满足条件后自动执行，及其保留期。
- 分支清理是否只针对本地分支；本轮未要求远程分支清理。

## 6. 持久化、架构与恢复

| ID | 已确认需求 |
|---|---|
| C23 | 使用 SQLite 持久化项目、任务、执行状态、Review 结果和日志。 |
| C24 | 任务状态以 Runner 为准，确保重启后可恢复。 |
| C25 | n8n 负责流程编排、审批、等待和通知。 |
| C26 | Python + FastAPI Runner 负责任务调度、状态机、CLI 调用和 Git 操作。 |
| C27 | 使用 Docker Compose 统一部署和管理服务。 |

流程可配置需求没有取消 Runner 的权威状态职责。流程定义放在哪里、n8n 与 Runner 分别执行哪些节点，仍需明确。

恢复方案与验收需覆盖残留进程、重复请求、已执行但未写回数据库的 Commit/Merge，以及清理中断。实际副作用与数据库状态不明时，不能直接假定成功或盲目重试。

## 8. 非编程产物、权限与实施顺序

| ID | 已确认需求 |
|---|---|
| C29 | Agent 默认只能操作指定仓库和任务工作区。 |
| C30 | Review 尽可能采用只读权限。 |
| C31 | 默认禁止自动 Push 和部署。 |
| C32 | 支持人工审批和运行限制。 |
| C33 | 先实现基础功能及自动化测试，再逐步接入真实 Agent 和 n8n 自动循环。 |
| C49 | 非编程任务按产物与验收证据完成，不强制 Git 流程；记录产物类型、位置、内容摘要、版本和验收证据，支持后继节点消费。 |
| C50 | 外部发送或写入等副作用需单独授权，并定义幂等或结果核对机制；执行结果未知时不得盲目自动重试。 |

非编程任务需要声明自己的工作区、输入、产物和操作范围。具体首批任务类型、验证方式和外部工具接入仍待确定；本基线没有默认授权外发、外部系统写入或新增连接器。

Worktree 是工作目录隔离手段，权限隔离、凭据范围和网络访问策略需要单独设计。清理必须保护未保存和未集成成果，不能将普通重试当作强制删除或撤销外部操作。
