# AgentAutomation 分阶段验收清单

- 更新日期：2026-10-17。
- 依据：[当前需求基线](requirements-current.md)；取舍背景见 [需求分析](requirements-analysis.md)。
- 状态：验收规格，尚未实现或执行测试；下文描述目标行为，不代表已有能力。
- 本文取代原先平铺的 30 项验收，按功能名称关联需求，不另建一套需求编号。

## 1. 首版验收边界

首版以本地单机、单 Runner、一个活动项目和该项目的一个仓库为范围，允许注册多个目标仓库。
首发暂以当前 Windows 环境验收，Runner 和 CLI 在主机运行，n8n 通过 Docker Compose 管理；最终部署选择以需求基线为准。
Windows 验收通过不代表 macOS、Linux 或全容器 CLI 执行已经支持。

保留一个开发预置流程和一个本地文档/分析流程。n8n 负责基本编排、判断、审批和等待，Runner 负责权威状态、执行和 Git 门禁。
不要求首版实现任意流程 DSL、通用资源调度器、外部连接器平台或完整可视化编辑器。

普通参数可以使用已记录的默认值；按节点类型检查必要输入。只有缺少关键输入、必要能力或授权时才阻止执行。
审查/判断的机器决策结果需要结构化；报告正文、日志和文件产物不强制转换为严格 JSON Schema。

## 2. 首版必过：12 组

### 项目注册与运行范围

能注册至少两个仓库，选择其中一个项目及其仓库运行；任务、产物和工作区归属可查。
第一版不同时运行第二个项目，不需要跨仓库任务。
给定有边界目标，能生成带依赖和验收标准的任务，并在完成后推进后续可执行任务；目标满足或触发上限时结束，无可执行任务时等待而不空转。

### 基本并行与依赖

配置允许时，两个独立任务实际重叠执行，并使用各自 Worktree/分支；有依赖的任务等待所需前置成果。
最大并发数生效；共享独占资源可用简单具名锁或串行解决，并显示等待原因，不要求自动发现全部语义冲突。

### 两种 CLI 与节点配置

Claude Code CLI、Codex CLI 分别完成小型任务；配置按项目默认 → 任务 → 节点覆盖，Coding/Review 可用不同 Agent/模型。
保存实际有效配置；不支持的配置明确报错，或走预先配置且记录在案的回退，不能静默替换。

### 新会话与有界修复

Planning、Coding、Review、Fix 及复审均为独立新会话，通过任务材料交接上下文。
Review 请求修改后能 Fix、复审；达到重试、Review 轮数或运行限额后停止，不重置计数绕过上限。

### 基本节点、判断与审批

开发流程能插入基本判断、审批与等待，按通过、拒绝及超时配置继续或停止；未选分支不会造成永久等待。
Runner 校验实际状态和门禁，n8n 重复请求或回调不会重复启动同一有效操作；无需自建通用流程引擎。

### Review 与任务提交

Review 输出非法、缺失、截断、异常退出或候选不匹配时，不得创建任务提交；必要检查失败也不得通过。
任务提交对应获批内容；Review 后内容变化需要重新验证并取得适用审查，不能把未审修改混入提交。

### 有序集成与组合验证

采用一种保留历史的本地 merge 方式，向同一目标分支串行集成；先验证候选，再按策略更新目标。
无冲突、无新增改写时可复用任务 Review 并运行集成检查，不强制为机械合并再做完整 Agent Review。
组合检查失败不更新目标；目标 HEAD 前移后核对候选并重新验证，不覆盖外部新提交。

### 冲突停止与人工处理

出现合并冲突时停止该项集成，保留任务成果与现场，允许人工处理；首版不要求自动冲突修复。
人工解决产生的修改需独立针对性 Review 和必要检查，通过后才能继续；其他任务是否推进取决于依赖和资源。

### 手动安全清理与结果区分

支持人工触发清理已合并的本地任务 Worktree/分支；有活跃进程、未保存改动、未集成成果或占用时拒绝正常清理。
所需证据归档后才删除临时现场；任务、集成、清理结果分别记录，清理失败不否定已完成成果，也不删除无关资源。

### 一个非编程流程

本地文档或分析任务可生成文件并完成验收，无需 Worktree、Commit 或 Merge；记录产物位置、版本或内容摘要及验收结果。
后继节点可消费产物，Git 集成和 Git 清理标为不适用；不要求首版接入消息发送或远程系统写入。

### 基本控制与可人工恢复

SQLite 持久化任务、尝试、结果和日志；暂停阻止新执行，取消/超时按平台能力停止进程树，迟到结果不推进 Git 操作。
重启先停止新调度并核对进程、Git 和数据库，再确认重试或人工恢复；不丢成果、不重复并发修改、不将未知结果记为成功。
调用次数、时间、重试和 Review 轮数限制生效，空队列不反复调用 Planner；费用估算不冒充精确金额硬上限。

### 首发环境与权限边界

在首发 Windows 环境验证两种 CLI、新会话、含空格/中文路径、执行取消，以及适用的 Worktree、合并和清理。
范围限定可信本地仓库，记录并验证 CLI/执行环境实际权限；不把 cwd 或 Worktree 当成沙箱，不默认 Push、部署或暴露无关凭据。
不能满足必要权限的执行不得静默放行；首版不承诺抵御任意恶意仓库或脚本的跨平台强隔离。

## 3. 引入或启用相应能力时必过

| 能力 | 条件验收 |
|---|---|
| 自动集成与扩展审批策略 | 仅在明确启用后按配置放行；审批绑定内容和目标版本，拒绝、过期及迟到回调不能授权新候选。未启用时走人工确认，不要求先实现全部策略。 |
| 项目自定义检查 | 配置为必要的检查必须实际执行并留存结果；失败或工具缺失不能伪报通过。不要求所有项目提供同一套检查或复杂证据协议。 |
| 外部发送或写入 | 实际引入连接器时才验收独立授权、幂等或结果核对；未知结果不得盲目重试。首版未接入时标记不适用。 |
| 新平台或全容器执行 | 宣称支持前，分别验证认证、路径、进程终止、恢复和适用 Git 操作；未验证的平台/部署方式列为未支持，不阻塞首版单平台验收。 |

## 4. 后续增强，不阻塞首版

- 通用流程编辑器、任意节点插件和复杂分支/汇合，通用资源发现与调度。
- 自动接管、通用租约、复杂事件投递与自动无缝续跑。
- 自动冲突修复、squash/rebase 等更多集成方式、自动清理与保留期调度。
- 更多非编程任务和外部连接器、多平台同等支持；精确费用硬限制仅在 CLI/账户能力可验证时承诺。

## 5. 验收记录

每组记录通过、失败或不适用及原因，保留实际平台/CLI 版本、有效配置、任务与尝试标识和必要日志。
代码场景补充基线、审查候选、提交与集成结果；产物场景保存文件与摘要。普通默认值可直接使用并记录，无需为每次运行手填全部配置。
先用 Fake Agent 验证基础流程和故障，再分别接入真实 CLI 与 n8n；当前文档更新不代表已通过任何功能验收。
