# AgentAutomation 需求验收标准

- 更新日期：2026-10-17。
- 依据：[当前需求基线](requirements-current.md)；设计背景见 [需求分析](requirements-analysis.md)。
- 状态：需求验收规格，尚未执行测试或实现功能。下列“预期”是目标行为，不是已验证结果。
- 用途：为确认需求提供可观察的通过条件；内部状态名、数据库字段和 CLI 参数由实现方案决定。

## 1. 验收前置配置

每次验收明确项目、任务流程版本、输入与产物版本、Agent/CLI/模型配置、必要检查、审批策略、并发/预算上限及支持平台。代码集成场景额外明确基线、目标分支、合并方式、集成检查和清理保留策略。

具体值未配置或必要能力缺失时，应明确拒绝启动或进入可解释的等待状态，不得静默选择模型、假定审批通过或扩大权限。首发平台和默认策略尚未确定，不阻碍先使用显式测试配置验证机制。

## 2. 功能与故障验收矩阵

| ID | 对应需求 | 输入或触发 | 必须观察到的结果 |
|---|---|---|---|
| AC01 | C02、C04、C15 | 注册两个目标仓库，第一版启动一个活动项目 | 注册记录均保留；项目内可有多个任务；不会因此同时启动第二个项目 |
| AC02 | C14、C15、C40 | 两个依赖独立、资源可用的 READY 任务，配置允许并发 | 两个执行时间存在实际重叠；各自输入、会话、工作区和结果可区分 |
| AC03 | C14、C15、C40 | 存在前置依赖、共享独占端口或额度不足 | 不满足条件者等待或串行，原因可查；后继取得所需前置成果后才运行 |
| AC04 | C07、C08、C17 | Coding 后 Review 请求修改，再执行 Fix 与复审 | 各 Agent 尝试均为新会话，材料可追踪；Fix/Review 不重置总轮数和预算 |
| AC05 | C05、C34–C37 | 配置有输入输出、条件、审批和汇合的任务流程 | 校验契约并按结构化结果路由；未选分支跳过；汇合按配置结束而非永久等待 |
| AC06 | C32、C36 | 审批拒绝、超时、要求修改或重复/迟到回调 | 走明确路径；未获准动作不执行；旧版本审批不能批准新内容，重复回调不重复执行 |
| AC07 | C17、C37 | Review/Fix 达到配置次数或预算上限 | 循环停止并记录原因，不能重新创建尝试以规避总限额 |
| AC08 | C11–C13、C35、C38 | 项目、任务和节点分别配置 Agent/模型，Coding 与 Review 选择不同组合 | 项目→任务→节点覆盖准确；适用权限限制仍生效；保存最终有效配置和来源 |
| AC09 | C39 | 指定不可用或不受支持的模型/CLI 配置 | 明确失败，或走预配置且记录在案的回退；不静默换 Agent/模型 |
| AC10 | C09、C10、C22 | Review 结果缺失、非法、截断、异常退出或与候选不符 | 不创建任务提交；错误和处理方式可查，不能用自然语言替代有效结果 |
| AC11 | C10、C22、C41 | 任务通过 Review 后候选、暂存内容或验收证据发生变化 | 旧批准不能用于提交改变后的内容；重新验证并取得适用 Review；提交树可核验 |
| AC12 | C19、C40、C41 | 两个任务并行编码并先后请求更新同一目标分支 | 工作区互相隔离；集成更新串行执行；任务提交及集成前后提交可追踪 |
| AC13 | C41、C44 | 两个任务分别通过，但集成候选的组合测试失败 | 不更新正式目标分支，不记录集成交付成功；保留各任务成果；依赖按定义阻塞 |
| AC14 | C41、C42 | 集成候选验证/审批后，目标 HEAD 被其他操作推进 | 旧候选/批准失效，重新生成或核对并重验证；不会覆盖目标新提交 |
| AC15 | C07、C41、C43 | 出现合并冲突 | 按配置进入人工等待或有界的新 Fix 会话；解决后的内容重新验证和 Review，超限保留现场 |
| AC16 | C10、C22、C41 | 集成需要创建新的提交 | 先对拟提交候选完成适用 Review，再创建最终提交；不能借集成绕过提交门禁 |
| AC17 | C44、C46 | 任务及集成已完成，后续清理失败 | 三类结果分别可查；任务/集成成功仍保留，清理单独重试；不虚报撤销成果 |
| AC18 | C21、C45 | 清理目标存在活跃进程、未保存改动、未集成成果或资源占用 | 正常清理被阻止，记录原因并保留现场；不自动强制丢弃 |
| AC19 | C21、C45、C46 | 合格成果和证据归档后清理，清理中断或重复请求 | Worktree 与分支步骤分别记录，可安全补做；不删除无关路径、分支或同名新资源 |
| AC20 | C01、C34、C44、C49 | 非编程任务输出文档或结构化数据，流程不含 Git | 按产物验收完成；位置、摘要、版本及证据可查；集成/Git 清理不适用，后继可消费产物 |
| AC21 | C29、C50 | 外部写入未授权，或已授权操作执行结果未知 | 未授权动作不执行；已授权未知结果通过幂等/核对处理，不能盲目重复发送或写入 |
| AC22 | C23、C24 | 重复触发、Runner 重启或租约过期但旧进程仍在运行 | 状态可恢复，旧进程先核对；同一任务无两个有效修改者，迟到结果不覆盖新执行 |
| AC23 | C24、C41、C46 | Commit/集成/清理已产生副作用但数据库未写回时崩溃 | 恢复核对实际成果，补记或等待处理；不盲目重复操作或虚报成功 |
| AC24 | C16 | 并行节点运行中暂停、取消或超时 | 暂停后不启动新节点；取消/超时按政策终止进程树；迟到结果不能推进提交/集成 |
| AC25 | C17、C40 | 多个任务同时竞争最后一份预算/并发额度 | 额度协调生效，不因并发超出已声明可强制执行的限制；费用估算与硬上限明确区分 |
| AC26 | C18 | 空队列、等待审批、依赖阻塞或达到停止条件 | 等待/阻塞/完成/停止原因区分；无任务时不反复调用 Planner 空转 |
| AC27 | C24–C26、C32 | n8n 重启或重复发送节点/审批请求 | Runner 的状态与门禁仍有效，调用幂等；n8n 不可直接改任务状态绕过流程 |
| AC28 | C28、C47、C48 | 在每个声明支持的平台使用含空格/中文路径运行任务 | 在该平台验证执行、进程树取消、恢复及适用的 Worktree/集成/清理；记录实际支持矩阵 |
| AC29 | C29–C31 | Agent 尝试访问无关目录、修改权威状态或未经授权 Push/部署 | 执行边界拒绝，不能只靠提示词；Review 动态验证不修改获批候选 |
| AC30 | C33 | 引入真实 CLI 或 n8n 自动循环前 | 基础流程先有 Fake Agent 自动测试；真实 CLI 分别验证版本、模型、新会话、结果与取消能力 |

## 3. 验收证据

验收记录至少保留测试环境、平台及 CLI 版本、流程与输入版本、有效配置、任务/节点/尝试标识、结果和失败原因。代码场景保留基线、候选、任务提交与集成目标记录；产物场景保留内容摘要和验证证据；清理前将所需证据移出临时工作区。

并行能力应使用执行时间重叠证明；独立 Review 应使用独立会话及输入材料证明；集成正确性应使用组合验证证明。CLI 正常退出、Agent 自述成功或数据库状态标签本身不足以证明这些条件。

## 4. 仍需选择的具体政策

本验收规格不决定目标分支名、合并方法、自动放行条件、默认审批点、首批非编程任务类型、默认模型/回退、并发和预算数值、清理保留期、首发平台或容器/主机执行方式。这些选择须在相应功能实施与验收前给出显式配置。
